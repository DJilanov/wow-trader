## Comparison method

The native Go runner uses the same pinned Forever combat engine and audited database as the
browser. Browser capture obtains each of the 23 named DPS builds with matching gear, talents,
APL, spec options, race, buffs, consumes and professions. No player-provided account data or
credentials are collected.

The benchmark is one level-63 target for exactly 300 seconds. Free Tier 1 bonuses and equipment
swapping are disabled. A baseline and candidate always share the same settings apart from gear.
Class-default buff contexts differ; the numbers are **not** a cross-class damage ranking.

1. Freeze gear first for legal talent/APL search. Preserve measured incumbents through noisy
   screening and retain meaningfully distinct allocations, rather than filling finalists with
   combat-equivalent utility-point swaps. Original, imported reference and generated seeds compete.
2. Fix the independently validated talents/APL for equipment search. Sweep all eligible armor,
   weapons and ranged items, ordered weapon pairs, accessory pairs and joint set proposals.
   Legal duplicate non-unique rings are included. No item-level floor or accessory EP cutoff;
   EP controls ordering, not admission. Set proposals enumerate all subsets of the per-slot
   set candidates. The expanded Alliance Fury sweep tests 26,753 legal ordered weapon pairs.
3. Use 80-iteration screening, a broader 500-iteration recheck and top-four 2,000-iteration
   comparisons including the incumbent. Selection-stage gains are exploration, not proof.
   Optimize reviewed static and deterministic scripted enchants and repeat until stable, with
   a six-pass safety limit. Known raid-only recipe/reward enchants remain excluded. Provisional
   weapon procs require an explicit baseline policy and actual browser opt-in for final proof.
4. Independently validate complete gear at 20,000 iterations per loadout on two fresh seeds.
   A non-converged safety-limit exit is not completion. Provisional proc enchants remain a
   separate opt-in model question; static-only results must not be called unrestricted maximum.
5. Create an immutable feedback baseline from completed gear evidence, revalidate equipment,
   and rerun talents/APL against that actual gear. Re-optimize equipment if the chosen talents
   or rotation change. Keep the incumbent when independent checks do not establish a gain.

This is a reproducible feedback/local search, **not proof of global BiS**. Weapon-style alternatives,
profession/race choices, fight lengths, AoE, target resistance, every possible set combination and
acquisition cost still need their own scenarios. Incomplete beta mechanics and unmodeled effects
can alter ordering. Every promoted set must identify its race/professions and provisional IDs.

### Resumable feedback command

`pnpm simulator:prebis:feedback --baseline=<frozen-baseline.json>` runs the reviewed Fury or Arms policy
through talent/APL search, equipment search, immutable equipment feedback and repeated talent
checks. `--gear-review=<completed-gear.json>` adopts an existing completed gear run first.
It never advances to another spec or publishes presets. Other specs still need their individual
talent/rotation policies; this command does not claim they have been optimized.

State is saved after each completed action under
`artifacts/forever-simulator/optimization/feedback-sessions/<identity>/session.json`. Repeating
the command reuses identical completed actions and the existing measurement cache. Inputs,
algorithm/data/UI-release fingerprints and the freshly compiled native binary identify a session;
changed evidence is rejected rather than silently trusted. A shared generated `active.lock`
prevents simultaneous feedback drivers. Only a confirmed-dead owner's lock can be recovered.
Do not launch this alongside a manually running optimizer: that older command is not managed
by the driver's lock. Interrupting the driver stops its current child and retains completed steps.

A no-gain talent pass only closes the loop when the preceding gear run converged and its
recorded pools cover all currently eligible items, including low-level and stat-light accessories,
with the full compatible deterministic/provisional-policy enchant sweeps. Narrow older reports
are reoptimized. Completion also requires the real browser/native check and the existing linked
four-seed review. A bounded `--max-rounds=6` limits full feedback cycles; hitting it returns
`feedback-limit-reached` with exit code 2, never a completed recommendation. An explicit higher
limit (up to 20) can resume the same session. A reviewed session remains research, not global
BiS or a public-default promotion.

For close comparisons, add `--validation-iterations=100000` to the driver and final-rotation
command. Only 20000 (default) and 100000 are supported. The chosen precision is fingerprinted
and propagated to both talent and gear checks; a completed 20k gear report does not meet a
requested 100k run. Four final ranges then represent 400k disjoint iterations. Screening is
unchanged and matching measurements remain reusable. No larger-precision claim is made from
the completed 20k evidence.

Talent and gear proofs both enforce the requested minimum count. Independent A/B ranges use one
worker-pool batch, retaining exact job/cache identities and identical-request deduplication;
actual native serial/parallel combat results match. The per-job watchdog scales with requested
work (15 minutes at 100k, bounded at 30 minutes) while the worker pool remains capped at six.
